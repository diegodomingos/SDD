### What the electron-vite `react-ts` Template Provides
- `electron.vite.config.ts` — Vite (renderer HMR) + esbuild (main/preload fast rebuild)
- Three separate tsconfigs: `tsconfig.json` (root), `tsconfig.node.json` (main/preload, Node lib), `tsconfig.web.json` (renderer, DOM lib)
- `src/main/index.ts` — BrowserWindow creation entry
- `src/preload/index.ts` — minimal contextBridge scaffold
- `src/renderer/main.tsx` — React entry
- `electron-builder.yml` — packaging config stub
- `resources/icon.png` — app icon placeholder

### TypeScript Process Separation (Architecture Constraint)
electron-vite enforces separate TypeScript compilation per process. Imports crossing process boundaries are illegal at the code level:
- `src/main/` and `src/preload/` → compiled under `tsconfig.node.json` (Node.js types only)
- `src/renderer/` → compiled under `tsconfig.web.json` (DOM types only)
- `src/shared/` → accessible to both via root `tsconfig.json` (pure TS, no platform-specific types)

**`src/shared/` does not exist in the scaffold** — create it now so Story 1.2 (`ipc-types.ts`) has a home.

### better-sqlite3 Native Module — Critical Gotcha
`better-sqlite3` is a native Node.js addon compiled to a `.node` binary. It must match the exact Node.js ABI used by Electron, not the system Node.js:
- electron-vite handles main-process externals automatically — `better-sqlite3` will NOT be bundled, it will be `require()`d at runtime
- If `npm run dev` fails with `NODE_MODULE_VERSION mismatch` or `was compiled against a different Node.js version`, the native binary needs rebuilding:
  ```
  npx electron-rebuild -f -w better-sqlite3
  ```
  Or add to `electron-builder.yml`:
  ```yaml
  nativeRebuilder: legacy
  ```
